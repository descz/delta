Delta Agent — documentation

What the agent does, exactly: the loop, the tools, the session format, the CI surface, the extension contract. The same text ships inside the binary as delta docs.

Intro

Delta is a terminal coding agent: one C11 binary, no runtime dependencies, working with the model you choose. You ask in your own words; it reads and edits files by exact blocks, runs commands, handles git, searches the web, keeps memory and speaks MCP.

A turn is prompt → provider (streaming) → tool calls → results → next step until the model answers without asking for a tool. Delta owns the loop and the tools; the model only asks.

limits · env overrides
DELTA_MAX_STEPS      200      steps in one turn
tool output          200 KB   per tool result (process killed at the cap)
context              8 MB     per request; above it, emergency prune (4 outputs x 20 KB)
empty provider turn  6 nudges after an HTTP 200 with nothing inside, then a real error

Install

Every download is the installer: it asks for the data folder, copies the binary, puts delta on your PATH and creates the shortcut. No admin, no Node, no Python.

releases · per platform
# windows 10/11 x64 - double click, or the zip
Delta.exe

# linux x86_64 - self-extracting installer (needs curl at runtime)
chmod +x delta-linux-x86_64.run && ./delta-linux-x86_64.run

# macOS 11+ - source package, builds locally
xcode-select --install
unzip delta-macos-source.zip && cd delta-macos-source && ./INSTALAR-MAC.command

Windows may warn on SmartScreen the first time (not code-signed): More info then Run anyway. The installer reopens with delta --setup. Linux was verified in WSL — the desktop layer (.desktop, GNOME favorites, clipboard) was not exercised on a real desktop. macOS ships source only; the native parts were never run by the author.

first run
delta                    # opens the CLI (always a new chat)
/login                   # pick the provider, paste the key
/projects ~/dev/my-app   # where it works (saved for next time)
read src/main.c and explain the flow

delta continue           # reopens this folder's last chat, thinking included
delta update --check     # only reports; `delta update` installs

Config

Everything lives in one folder, chosen at install time (default ~/.deltaCore). config.json holds provider, model, language, thinking level, verbosity and the project folder; auth.json holds one API key per provider.

config.json
{
  "provider": "opencode-go",
  "model": "deepseek-v4.1-flash",
  "baseUrl": "https://opencode.ai/inference/go/openai/v1",
  "language": "pt-BR",
  "thinkingLevel": "max",
  "verbosity": "low",
  "maxTokens": 8192,
  "projectDir": "",
  "updateCheck": false
}

Slash commands that matter here: /login, /models (catalog from models.dev), /thinking, /verbosity, /projects, /status, /docs. Any OpenAI-compatible endpoint works through baseUrl.

Tools

read write edit undo bash ls find grep graph plus the unified families fs shell git web memory code assert agent extend skills mcp extensions, each taking an op. Every write keeps an undo snapshot; bash has a timeout, converts Windows OEM output to UTF-8 and is killed when ESC/Ctrl+C asks to stop (exit 130).

Sessions

One JSONL per session, per folder. delta always starts a new chat, delta continue reopens the last one with the full history and the model's thinking.

sessions · export
~/.deltaCore/sessions/----/_.jsonl
{"type":"session","version":3,"id":"...","cwd":"..."}
{"type":"message","message":{"role":"user|assistant|tool","content":"...","thinking":"..."}}

delta export            # markdown transcript of the last session
delta export --json     # NDJSON of the same messages

CI surface

One JSON event per line, ready for jq or a CI step. Exit codes: 0 ok, 1 agent error, 124 command timeout.

ndjson events
delta -p "review src/" --json

{"type":"text","text":"..."}
{"type":"thinking","text":"..."}
{"type":"tool_call","name":"bash","args":"{...}"}
{"type":"tool_result","name":"bash","ok":true,"seconds":1.1,"bytes":10}
{"type":"turn_end","in":1234,"out":456}
{"type":"error","message":"..."}

Extensions

One manifest can change several parts of the harness at once. Files with a single kind (tool, skill, command, mcp, hook) keep working.

~/.deltaCore/extensions.json
[
  {
    "name": "guardrails",
    "enabled": true,
    "prompt":   "rules appended to the system prompt",
    "tools":    [{"name": "x", "arg": "cmd", "desc": "...", "schema": "{...}"}],
    "commands": [{"name": "deploy", "arg": "optional prompt", "exec": "cmd"}],
    "hooks":    [{"event": "tool_call", "arg": "cmd"}],
    "ui":       {"status": "cmd"}
  }
]

The agent can create one itself: extensions tool, op=add for a single capability or op=bundle for a whole manifest. It takes effect on the next tool call.

Hooks

A hook is code, not a prompt: the harness runs it, so a blocked call never happens. The payload arrives as a JSON file path in argv[1]; the reply is JSON on stdout. 5 s timeout, 8 KB cap, fail-open. Paths with spaces must be quoted inside arg.

events
tool_call      {"block":true,"reason":"..."} | {"args":"{...}"}
tool_result    {"output":"..."} | {"append":"..."}
user_message   {"block":true,"reason":"..."}     before any request leaves
turn_start     ignored reply                     before each provider call
turn_end       ignored reply
session_start  once per process

Security

Requests go only to the provider you configure. History, keys, memory and skills stay in your local folder, and every file is written to a temporary and swapped in one step, so two windows never read half a config.

Honest limits: keys are plain text in auth.json (the OS keyring is not wired yet); there is no system sandbox — hooks and extensions run with the same permissions as Delta; only install extensions you trust.

Limits

macOS is source-only, with the native layer untested. Linux desktop integration is untested. The UI is not extensible: no in-process plugin, so no widgets, keys or overlays from an extension — what an extension can change is behaviour (prompt, tools, commands, hooks, footer status), not pixels.

FAQ

Do I need an API key?

Yes, from a provider you use (OpenAI, Anthropic, OpenRouter, DeepSeek, opencode and others). /login asks for the key once, stores it per provider in auth.json and picks a default model.

Does it run offline?

The program runs, the model does not. Without network the CLI, sessions and the local tools still work, but the agent cannot talk to the provider.

Which platforms are supported?

Windows 10/11 x64 (the reference platform), Linux x86_64 (builds and runs; desktop integration untested) and macOS from source. There is no prebuilt macOS binary.

Is there a Windows installer?

The download is the installer: double click Delta.exe, choose the data folder, and it copies the binary, sets PATH and creates the shortcut. No admin rights.

How big is it?

809 KB single executable on Windows, about 1.7 MB of private memory, zero runtime dependencies.

Which models can I use?

Any model in the models.dev catalog from the providers you connected — Anthropic, OpenAI, OpenRouter, DeepSeek, opencode and others. /models lists what your keys allow.

Can I use a local model?

If the server exposes the OpenAI-compatible chat API, point the OpenAI provider at its base URL (config baseUrl or --baseurl).

How do I change the model or the thinking level?

/models switches the model, /thinking sets the reasoning effort and /verbosity sets how much prose the reply carries. All saved in the config.

What is the context window shown in the footer?

The real limit.context of the current model, read from the catalog (1M for a 1M model), with 200k as fallback when the catalog does not know the model.

Does it support MCP?

Yes — JSON-RPC over HTTP or stdio. Servers live as one file each in mcps/, and their tools appear to the model like the built-in ones.

Can I add my own tools, commands, skills or hooks?

Yes, and they live in one manifest: an extension can declare tools, commands (a prompt, or an exec that runs and prints in the chat), hooks (intercepting tool_call, tool_result, turn_end, session_start, user_message and turn_start to block, rewrite or log), a prompt appended to the system prompt and ui.status for a third footer line. The agent can create them itself with the extensions tool.

Can it write and run code for me?

It reads and edits files by exact blocks, runs shell commands with timeouts and background jobs, handles git, and can generate code in any language. Two skills ship for that: deltamotion (video as C code to MP4) and 3jsskill (Three.js without a build step).

Where does my data go?

Only to the provider you configure. History, keys, memory and skills stay in your local data folder; each file is written atomically so parallel windows never corrupt it.

Is it open source?

Source-available and non-commercial. The code is public for study and personal or internal use, but the license forbids selling, charging for access and cloning. Sharing the unmodified copy, non-profit and with credit, is allowed. See the LICENSE.

Windows said the app is unknown. Is it safe?

That is SmartScreen because the binary is not code-signed: More info, then Run anyway. The source in the repository is exactly what builds that binary.

Was Linux tested on a real desktop?

Partially. Build, CLI, TUI, real streaming and self-update were verified on Linux (WSL, gcc 13). The desktop integration — .desktop entry, GNOME favorites, clipboard — was not exercised on a desktop session.
