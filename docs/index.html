apresentação

Um binário. Um agente.

O Delta conversa com o modelo e executa o trabalho de verdade: abre o arquivo, edita o trecho, roda o teste, lê o erro, corrige. Tudo no terminal, com o mesmo modelo mental de um editor.

01

Ele executa, não só responde

Lê e edita arquivos por trechos exatos, roda comandos com timeout, mantém jobs em background, faz diff e commit. O resultado aparece no chat, não numa aba separada.

02

Ele lembra

Sessões por pasta em JSONL: delta reabre o último chat daquela pasta com todo o histórico. Skills viram SKILL.md; fatos duráveis vão para a memória.

03

Você manda no meio

Digite enquanto ele trabalha. A mensagem entra na fila e ele corta a resposta no próximo fragmento para ler — sem esperar o turno terminar.

como ele pensa

O loop do turno

O agente é dono do loop; o modelo só pede. Cada pedido de ferramenta vira uma execução real no seu projeto e o resultado volta para o modelo decidir o próximo passo.

01Você escreve o pedido
02O modelo responde em streaming
03Pede ferramentas (JSON)
04Delta executa e devolve
05Repete até terminar

Render incremental

Cada bloco guarda a linha onde começa; o transcript é remontado a partir do primeiro bloco sujo. Frame típico de 0,5 ms mesmo com centenas de blocos.

Terminal nativo

Modo cru com ReadConsoleInput no Windows e termios no POSIX: mouse, colagem, redimensionamento, tela alternativa e atalhos com modificadores.

Rede enxuta

WinHTTP no Windows, curl no POSIX. SSE lido linha a linha, com abort imediato quando você interfere no meio do stream.

instalar

Do zero ao primeiro pedido em minutos

Cada download já é o instalador: pergunta a pasta, copia o binário, põe delta no PATH e cria o atalho.

Windows 10/11 x64

Delta.exe — programa + instalador num arquivo. Duplo clique abre a tela no navegador.

Linux x86_64

delta-linux-x86_64.run — auto-extraível, instala e deixa delta no PATH.

macOS 11+

Pacote com o código + INSTALAR-MAC.command: compila na máquina e instala o app.

# linux
chmod +x delta-linux-x86_64.run && ./delta-linux-x86_64.run

# primeiro uso
delta                    # abre o CLI (retoma o último chat desta pasta)
/login                   # escolhe o provedor e cola a chave
/projects D:\dev\app     # onde ele trabalha (fica salvo)

# no dia a dia
leia src/main.c e explique o fluxo
/terminal git status     # roda no shell e mostra a saída no chat
/copy                    # copia a última resposta
delta wiki               # abre esta documentação no navegador

faq

Perguntas curtas

Preciso de chave de API?

Sim, de um provedor que você use (OpenAI, Anthropic, OpenRouter, DeepSeek, opencode…). /login pede a chave uma vez e guarda por provedor em auth.json.

Roda offline?

O programa roda; o modelo não. Sem rede ele continua abrindo o CLI, as sessões e as ferramentas locais — mas não conversa com o provedor.

Por que C11?

Um executável sem runtime abre instantaneamente e não quebra com atualização de Node. A TUI, o parser JSON, o markdown e o cliente HTTP são todos escritos no projeto.

O Windows avisou que o app é desconhecido

É o SmartScreen por falta de assinatura digital: Mais informações → Executar assim mesmo.

E no macOS?

O binário precisa ser compilado na máquina — não há cross-compile confiável para Mach-O. O pacote traz um .command que confere as Xcode Command Line Tools e faz tudo.

Posso usar comercialmente ou fazer um fork público?

Não. A licença é source-available e não comercial: proíbe venda, cobrança de acesso e clone (fork público, pacote, binário ou rebranding). Compartilhar a cópia não modificada, sem fins lucrativos e com crédito, é permitido. Veja LICENSE.

Meus dados vão para algum lugar?

Só para o provedor que você configurar. Histórico, chaves, memória e skills ficam na sua pasta .deltaCore.
